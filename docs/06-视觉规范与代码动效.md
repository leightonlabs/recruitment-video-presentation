# 视觉规范与代码动效

本文件规定成片的色彩、字体、版面、动效与代码场景，配合[招聘视频方案](01-招聘视频方案.md)使用。数值同时写在[分镜数据](03-分镜数据.json)的 `design_tokens` 中，代码渲染直接读取 JSON；两处不一致时以 JSON 为准。

## 色彩

| navy_800 | `#0F2B46` | 主深底、岗位面板、浅底上的正文 |
| navy_700 | `#123E54` | 深底上的信息框、界面面板 |

| teal_500 | `#2DB4AA` | 浅底上的强调色 |
| amber_500 | `#F59E0B` | 深底上的“存疑”“待复核”“判断二”、通用模型的误判框，以及点云中的目标点 |
| amber_700 | `#B45309` | 浅底上的博士人数（与资料第5页一致） |

## 用词与语言

- 用词以客户文案为准：“数据标注”只出现在国家试点的正式名称中（如“数据标注先行先试”），不用来描述岗位工作；“标注”尽量不用，分别写作数据集配套、场景建模、目标框定、模型适配、场景验证。
- 屏幕文字以中文为主，除“AI”和客户文案中的“FDE”外不用英文：版本号写作“1.3 版”，编号写作“案例 017”“样本 023”，NLP 写作“自然语言处理”，3D 写作“三维”。
- 代码画面只作质感，可保留英文代码，但注释与字符串用中文。
- 以上由 `python3 tools/storyboard.py check` 按分镜数据中的 `copy_rules` 自动检查。

## 版面区域与安全区

**16:9（1920×1080）**

- 左右边距 128 px，上下边距 96 px。
- 章节标签固定在左上角（128, 96）；主标题在左上或左中（128, 420）。
- 字幕基线 y = 990，单行不超过 16 字；字幕与屏幕标题不放在同一区域。
- **竖版安全带：** x = 656–1264。AI 画面的主体、边界样本的目标区域必须落在这条带内，保证 9:16 中央裁切后成立。
- 文字区与主体区分开：点云、样本主体放在画面中部或中右，标题区不压主体。

**9:16（1080×1920）**

- 左右边距 72 px，标题起始 y = 220，字幕基线 y = 1540。
- 右侧 140 px、底部 320 px 留给平台按钮与文案，不放关键信息。
- 代码场景按各镜 `vertical` 字段重排（多栏改为纵向），不从 16:9 裁切。

## 动效

| 项目 | 规定 |
|---|---|
| 入场 | 0.5 秒，`cubic-bezier(0.22, 1, 0.36, 1)`，位移不超过 24 px，配合透明度 |
| 出场 | 0.3 秒，或直接随镜头切走 |
| 位移与镜头运动 | `cubic-bezier(0.65, 0, 0.35, 1)` |
| 描线 | 0.6 秒，沿路径匀速描出 |
| 计数 | 1.2 秒，先快后慢 |
| 文字停留 | 至少 1.5 秒，且不少于“字数 ÷ 9”秒 |
| 代码镜头推拉 | 每 5 秒缩放变化不超过 6% |
| 禁止 | 弹跳与弹性缓动、整屏高速穿梭、无目的的三维旋转 |

岗位卡、招聘总卡和片尾在入场完成后保持静止，只允许背景画面缓动。

## 青色连接线

- 4 px 圆头线，颜色 `#2DD4BF`，同色 8 px 模糊、40% 不透明的外发光；界面内细线为 3 px。起点带 10 px 方块节点。
- 三种动作：**描出**，沿路径画出；**流动**，一段 120 px 高亮沿路径移动，表示数据流向；**变形**，线段变为框、多边形或连接线。
- 出现位置：S01 描出真实边界 → S04 环形图高亮段延伸为线 → S05 穿过五张行业场景卡 → S06 连接三块界面 → S08 流程回环 → S09 三维框 → S10 视图引线 → S12 回环箭头延伸为横线 → S13 穿过三块画面 → S15 任务连接 → S17 描出成长通道 → S22 招聘流程时间轴 → S23 标题下延伸 → S24 片尾分隔线。
- 它是全片唯一允许跨镜头延续的图形元素，不另加其他装饰线条。

## AI 画面的统一处理

1. **调色：** 所有 A / I / R 画面套用同一份 `.cube` LUT：暗部抬到 `#0A1A2E`，阴影偏青，肤色保持自然暖色，饱和度 −10%；再叠 2% 颗粒和 15% 暗角。LUT 由代码生成，调整一次全片生效。
2. **帧率：** 24 fps 素材直接按 25 fps 变速使用；30 fps 素材按丢帧转换。不做插帧。
3. **屏幕与文字：** AI 画面中的屏幕背向镜头或虚焦。需要观众看清的屏幕内容一律切到代码画面，不在 AI 画面上贴屏。
4. **对齐叠加：** 与画面位置相关的框线只叠在静帧或锁定机位的片段上；锁定机位片段在首帧标定坐标，叠加前检查末帧是否漂移。
5. **截取：** 每段 5 秒生成后，只取动作最完整、形变最少的 1.2–3.6 秒。

## 字幕

Noto Sans SC 700，40 px，白字，2 px 深蓝描边加柔和投影；按标点切分，单行不超过 16 字，行尾不加逗号和句号。字幕由 `python3 tools/storyboard.py srt` 从分镜数据导出，烧录时与屏幕文字错开区域。S01、S24 的旁白与屏幕标题相同，不再加字幕。

## 渲染流程

1. **场景渲染：** 每个代码场景以 1920×1080（竖版 1080×1920）、25 fps 逐帧截图，输出无损中间文件；需要叠在 AI 画面上的层输出带透明通道的 PNG 序列。
2. **合成：** FFmpeg 按分镜数据拼接各拍：AI 片段先套 LUT、变速、截取，再与代码层叠加。
3. **声音：** 旁白、音乐、音效按 `vo.t`、`music`、`audio` 时间放置，音乐在旁白处自动压低。
4. **字幕与输出：** 烧录字幕后输出 H.264 成片，另存 ProRes 422 HQ 母版。

本仓库所在环境已实测：Chromium 无头渲染可正确显示 Noto Sans SC、JetBrains Mono、Long Cang 三款字体与 WebGL 点云；二维场景约 0.14 秒一帧，24 万粒子的三维场景约 0.4–0.6 秒一帧，全片 3750 帧单进程约 15–25 分钟，可多进程并行；FFmpeg 具备 x264 / x265、libass 字幕、三维 LUT 与透明通道合成能力。

**四、不做或做不到**

- 用代码渲染写实的人物、厂区或电影级三维穿梭；写实画面只来自 AI 生成或实拍。
- 在运动的 AI 镜头上追踪贴合标注；方案已规定只在静帧或锁定机位上叠加。
- 凭听感做专业混音与音色设计：响度、峰值等可以测量，但成片声音需要人工试听确认。
- 动作的流畅度与节奏感需要人工看预览片确认；代码侧按逐帧截图检查构图与文字。
